# Security Policy

## Supported Versions

At this stage, security fixes are applied to the latest state of the default branch.

## Reporting a Vulnerability

Please prefer GitHub private vulnerability reporting for this repository if it is enabled.

If private reporting is unavailable:

1. Do not open a public issue with exploit details, credentials, proprietary model files, or plant/process data.
2. Open a minimal public issue only to request a private reporting channel, and do not include sensitive reproduction material.
3. Include enough context to describe impact, affected files, and whether any secrets or proprietary data may be exposed.

## What to Report

Security reports are especially helpful for:

- committed secrets or credentials
- workflow or automation misconfigurations that could expose data
- unsafe defaults that could leak proprietary simulation artifacts
- supply-chain risks in repository automation or dependencies

Non-security bugs and documentation issues should go through the standard issue templates.
